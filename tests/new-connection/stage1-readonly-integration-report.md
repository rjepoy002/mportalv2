## Gate and read-only route

`MCO_STAGE1_DISPLAY_ENABLED=1` plus trusted `APP_ENV`/`MCO_APP_ENV` local/development is necessary, with loopback server/peer, local Host and no forwarding headers. Default is off. Staging HTTPS/nonloopback authorization is not implemented; the supported milestone is isolated local Apache only. Neither existing application nor preview flags grants display access.

The gate runs before session/identity access. GET/HEAD only; POST/PUT/PATCH/DELETE return 405. Anonymous sessions redirect to fixed relative `index.php`; inactive/unverified/missing identities receive 403. Private/no-store, nosniff and frame denial headers are retained. Infrastructure errors are generic.

The renderer captures the existing guarded prototype layout with empty synthetic context and the existing `stage1.v1-draft-20261020` contract. Before sending HTML it removes forms, editable controls, form action buttons, all embedded scripts/context and editor navigation. Fields become explanatory text; all five sections are visible. Only local theme/sidebar scripts are reintroduced. No draft, review proof, submit, upload or persistence service is imported. No applicant values are fetched. Display rendering requires PHP DOM/libxml, available in tested XAMPP.

The fixture rendering guard is defined only inside this authorized rendering path, followed by server-side conversion; it is not a global bypass exposing the editable prototype. The independent actual application gate stays default-off. Actual port-80 GET of the new display route returned **404**. No new sidebar link was installed.
